# V2.0 first increment: offline host contract preflight

Status: development candidate, not release acceptance. Based on PR #17 at
`2c630e1df4334042ce0d81ef9902fdd7a7202bee`. No main merge or version promotion.

## Implemented

`python3 collaboration/host_contract.py` asks the installed Codex binary to
export its protocol schema into a temporary directory. It does not start a model
turn, inspect credentials, change configuration or relax sandbox restrictions.
An explicit `--schema /path/to/TurnStartParams.json` can inspect a captured schema.
Generated projects receive the same tool at `.ai/tools/host_contract.py`.

The preflight checks whether the schema explicitly declares the required
`readOnly.access.restricted`, `readableRoots`, and `includePlatformDefaults`
fields. Missing declarations exit 2 with `BLOCKED_RESTRICTED_READ_NOT_DECLARED`.
Failure to generate or parse a schema exits 2 with `BLOCKED_SCHEMA_UNAVAILABLE`.
Local references are resolved with a bounded traversal; external references are
never fetched. Raw stderr, paths and server messages are not reported.

Exit 0 only means the schema declares these fields. It does not prove runtime
enforcement, authentication, native tool availability or business acceptance.
Live E2/E3 verification is still mandatory. This is an explicit preflight, not
an automatic fallback or a change to the adapter's access policy.

PR #17 diagnostics also now handle malformed non-integer RPC error codes without
raising a Python TypeError. Unknown codes remain OTHER; no server text is exposed.

## Actual local evidence

This cloud executor has Codex `0.167.0-alpha.4`, not the VPS's `0.167.1`.
Its generated `v2/TurnStartParams.json` declares readOnly with type/networkAccess,
but does not declare access/restricted/readableRoots. The new command returned
BLOCKED_RESTRICTED_READ_NOT_DECLARED and exit 2. This identifies a declared
contract gap on this executor; it does not establish the VPS rejection's cause.
