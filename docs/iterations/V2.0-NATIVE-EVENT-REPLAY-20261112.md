# V2.0 native-event replay boundary (candidate)

Based on PR #18, this increment changes only terminal V1 collaboration-tool
evidence handling. It does not start a native model, change access rights,
merge a release or clear a real-host acceptance gate.

## Reproduced defect

A completed wait observed before its child's spawn was ignored, but replaying the
same event ID after spawn caused it to count as a fresh completion. A new negative
unit test failed before the fix (`Fault not raised`). This is synthetic protocol
reproduction, not an observed VPS incident.

## Fix

Terminal tool-call IDs must be present and nonempty. Their first observed semantic
identity (tool, child, per-child state) is retained. Identical replay is ignored;
reusing an ID for a changed identity fails closed. An early wait can therefore not
be recycled into a late completion. A distinct fresh wait may still prove completion.
Empty child identities cannot produce proof. V2 activity event handling is unchanged.

Seven focused cases cover foreign parent identity, early wait ordering, replay,
multiple-child scope, duplicate idempotence, identity collision, and missing IDs.
Existing wait fixtures now explicitly use distinct terminal event IDs, matching the
required identifiable event shape. These are all fixtures, not live child proof.

Live VPS 0.167.1, sandbox enforcement, real AT-001 and total token coverage remain
unverified. Any real host omitting terminal event IDs must remain blocked rather
than weakening evidence requirements.
