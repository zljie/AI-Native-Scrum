## 2. 宿主能力契约 / 证据分级

| 层级 | 可证明 | 不可代替 |
|---|---|---|
| E0 安装/配置 | 二进制版本、登录状态、配置开关 | 模型调用成功与原生委派 |
| E1 fixture/CI | JSONL/RPC 解析、失败即阻断、协议负例、Bootstrap 一致性 | 实际宿主子线程 |
| E2 宿主 transport | 本机 app-server `initialize` / `thread/start` / `turn/start`、真正的宿主来源、权限 | `spawn_agent` 证据 |
| E3 原生子 Agent | 父 turn 内原生 spawn 事件与 child id、同一 child 的生命周期、可核验结果 | 业务能力或独立验收 |
| E4 真实项目业务闭环 | 当期任务事实、按需激活、交接拒收、版本失效、恢复、人工验收 | 生产部署许可 |
| E5 目标项目升级/回滚 | 真实已安装隔离项目升级与可恢复证据 | 生产安全或发行批准 |

`runtime_session` 是由控制器调用 `thread/start` 创建的独立线程；它不是父线程调用 `spawn_agent`。Fixture、Agent 自述、wait 工具成功、应用生成的结果 JSON 都不可单独升级为 E3。

`capabilities()` 不执行登录探测；`codex_app_server_installed=true` 仅表示可执行文件存在，`native_spawn_agent_supported=false` 表示框架尚未完成真实宿主验证，**不是** 证明该版本不具备该能力。

## 3. G02：只读协议兼容探针（由远程线程执行）

在经批准的隔离测试副本中，使用已登录宿主、相同模型与目标版本，**先不启动业务多 Agent 测试**：

1. 记录 `codex --version`、`codex app-server --help`、`multi_agent` 生效状态、项目 commit SHA；不得记录凭据。
2. 在同一受限只读契约下，分阶段验证：`initialize` 响应 → `initialized` → `thread/start` 返回 thread id → `turn/start` 返回 turn id → `turn/completed`。若有原始错误，仅提取 **请求阶段、JSON-RPC 数值 code、运行时退出码、是否断连、是否有原生回执**。
3. 分别记录隔离沙箱和已授权宿主执行路径的阶段结果。不把不同运行环境的 `RUNTIME_DISCONNECTED` 和 `RUNTIME_REJECTED` 归为一个根因。
4. 若 `turn/start` 返回 `-32602`，仅在受控环境中复核 **本机安装版本的生成协议契约**，重点比较 `readOnly.access` 是否仍被支持；不要凭旧版本文档猜测。无同等受限读取能力时 **BLOCKED**，不得改成 unrestricted/fullAccess。
5. 原始 stdout/stderr、RPC 的 prompt/context/文件绝不直接粘贴到公开 PR。必要时由远程操作者先审核脱敏，保留原始文件哈希与受限存储位置；公开版只保留可定位的安全错误类别。

框架候选诊断码示例：`RUNTIME_REJECTED_TURN_START_INVALID_PARAMS`、`RUNTIME_DISCONNECTED_THREAD_START`。这些仅说明阶段与标准错误类别，不证明错误发生于哪个具体参数。代码不输出来自宿主的 `error.message` 或 `error.data`。

**阻断条件：** 任一步返回错误、身份未获验证、受限沙箱契约无法维持、无法关联原始宿主来源，则 G02 不通过；不重复发送有副作用的 RPC 请求来探测。

## 4. G03：原生委派证明（须 G02 宿主协议成功后执行）

对 **真实父 turn** 至少固定以下项：本次授权记录/任务引用、Context Pack hash、父线程 ID、父 turn ID、原生 `spawn_agent` 工具调用、返回的不同 child thread ID、child 的生命周期与完成状态、结果引用。

- 接受 V1 `collabToolCall` 的 spawn + wait，但 wait 只有真实子状态 `completed` 才有效；或 V2 `subAgentActivity` 的 `started → completed` 同 child ID 和不变 `agentPath`。
- 对父 `turn/completed` 后延迟到达的 child completed，维持有界观察和严格父 thread/turn 检查；迟到不意味着可忽略来源。
- `interrupted`、重复冒用身份、事件反序、跨父 turn、多个 child 混入均拒绝“原生完成”的证明。
- 宿主原始事件/角色启动回执与框架 journal 脱敏散列关联；独立审查是否确有子 Agent（而非角色描述）。
- 若只能得到父线程与 wait / 结果而无法关联子 started+completed 或有效 spawn+wait 子状态，保持 **NOT_VERIFIED**；在未实际执行的用例上记 **NOT_RUN**。

## 5. G04：隔离设备台账 AT-001（独立远程线程拥有目录）

复用 `docs/iterations/COLLAB-TEST-001_maintenance-grade.md` 与 `V1.5-ROADMAP.md`。针对已存在的 SQLite `equipment` 表新增**可空**检修等级；不连接生产数据库。

| 用例 | 要求记录的可复核结果 |
|---|---|
| A：确实需要迁移 | Context Pack 绑定 schema/DAO/test SHA；架构前置判断→数据库专家按需启动→受控实现→架构后置复核；真实子线程与技能执行路径 |
| B：不需要数据库改表 | 基于真实代码证据标记数据库专家跳过原因；无伪造 DBA 活动 |
| C：交接拒收 | 接收侧独立指出遗漏，拒收导致下游阻断；旧 revision 保留，修正后重新审查 |
| D：需求/源文件变化 | 旧 Context hash、交接和测试 evidence 失效，原 run blocked；新授权建立关联的新 run，旧 history 不改写 |
| E：中断恢复 | 覆盖“无副作用 / 已发生副作用 / 无法确认”；未知或已发生时不得自动重试；人工核对不等于自动放行 |
| F：权限与重复操作 | 越权、生产/破坏性操作拒绝；幂等与重复写入验证；保留原始测试退出码 |
| G：最终验收 | 测试、架构复核与当前源码 SHA 一致；接收者真实独立审查并签署验收，缺项为 BLOCKED |

业务测试程序、建模数据、产物由远程线程维护；**框架侧不对其目录做任何写入**。

## 7. 交接回框架侧的最小脱敏证据清单

建议由远程线程维护一个隔离 `evidence/host-probe-summary.json`，至少记录：`repo_sha`、`cli_version`、`auth_observed`、`multi_agent_config_observed`、`probe_environment`、`sandbox_contract`、各 RPC `phase/status/error_code`、`process_exit_code`、`native_child_event_count`、`parent_turn_scope_verified`、`evidence_hashes`、`outcome`。文件不含身份凭据、原始 prompt、秘密路径或原始用户数据；字段缺失为 `unknown`，不是成功。

在框架 PR 中可公开提交脱敏的失败类别、SHA、测试命令与结论；原始受限证据由远程线程保管并以哈希交叉引用。当前本 PR **没有访问远程 evidence 文件，也没有取得原始服务端错误码**。
