## 当前首批代码的边界

`collaboration/project_context.py` 提供 `project-context-request/v1` → `project-context-pack/v1` 的只读、显式来源快照和漂移校验。它不自动扫描仓库、不读取秘密、不调用模型、不生成数据库设计、不判断是否应激活 Agent、不批准任务，也不修改现有业务状态。

示例请求（必须使用项目真实文件，不要照抄为批准记录）：

```json
{
  "schema": "project-context-request/v1",
  "goal_ref": "raw/goals/GOAL-001.md",
  "task_ref": "raw/tasks/TASK-001.md",
  "sources": {
    "architecture": ["docs/architecture.md"],
    "database": ["migrations/001_init.sql"],
    "interfaces": [],
    "implementation": ["src/service.py"],
    "tests": ["tests/test_service.py"],
    "requirements": []
  }
}
```

在源码仓库执行（未内嵌到目标项目之前）：

```bash
python3 collaboration/project_context.py --root . build --spec intake/context-request.json --output generated/reports/context-pack.json
python3 collaboration/project_context.py --root . check --pack generated/reports/context-pack.json
python3 -m unittest discover -s collaboration -p 'test_project_context.py' -v
```

输出为源文件引用、大小和 SHA256，不含源文件正文。目标项目集成需后续完成 Bootstrap 资产内嵌和版本升级验证；当前不把仅在源码仓库可运行说成已经安装到业务项目。

## 黄金路径验收需求 V15-AT-001

隔离测试场景：已有设备台账新增可选“检修等级”，并支持编辑与筛选。已存在 `equipment` 表；需先检查真实迁移、数据访问和测试路径，架构 Agent 前置评估，数据库专家按需设计与迁移，研发适配，测试独立验证，架构 Agent 后置更新架构事实。

必须证明：
1. 只有存在数据库变更证据时才激活数据库专家；无需改表时正确跳过。
2. 真实原生委派有宿主实例回执；fixture 不能冒充。
3. 数据契约变化使旧交接与旧测试证据失效。
4. 测试失败退回责任任务，保留旧 revision，不能直接宣布完成。
5. 中断后恢复不重复授权、写入或执行已完成的副作用。
6. 破坏性数据库操作必须停在独立授权边界。
7. 后置架构复核记录与实际代码版本绑定；架构提案不自动扩大范围。

当前尚未完成真实原生宿主验收、V15-02～07、业务项目升级或 V1.5 发布，均标记 NOT_RUN / IN_PROGRESS。通过 CI 只能证明确定性实现与回归，不能证明 Agent 已真实参与。
