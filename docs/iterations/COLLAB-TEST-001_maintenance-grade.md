# COLLAB-TEST-001｜设备台账“检修等级”协作验收需求

状态：隔离验证需求；不是 jlcase/JLSH 已批准的生产需求。
来源：ANS-V14-P0-COLLAB-PRD-001 附录A；用户要求用新需求测试通用协作可观测性。

## 业务目标与样例假设

为已有设备台账增加可空的检修等级，允许编辑者修改、按等级筛选，并保持历史设备
的ID、名称和数量不变。本隔离样例固定采用A/B/C三个等级，历史设备默认空值；
这不是替真实业务定义检修分级。在实际项目中必须重新核对真实表/接口和业务口径。

## 本轮样例范围

使用Python标准库与SQLite，包含既有equipment表、单独SQL迁移、数据访问接口和8项
可执行测试；没有真实生产数据库、外部通知、完整HTTP前端或浏览器验收。

期望激活产品、架构、研发、测试和独立数据库专家；没有发布影响则运维有合理跳过
原因。架构前置评估、研发读写分析、数据方案、测试设计、迁移/实现、独立验证，
最后架构基于实际结果复核。角色以同一协作协议工作，不用DB专用调度硬编码。

## 业务验收

| ID | 可观察结果 |
|---|---|
| EQ-01 | 新字段存在，历史设备ID/名称/数量保留，等级为空 |
| EQ-02 | 授权编辑者修改A/B/C；按等级筛选准确 |
| EQ-03 | 非法值被拒，旧数据不被覆盖 |
| EQ-04 | 允许恢复为空值 |
| EQ-05 | 重复执行迁移不丢数据、不重复加列 |
| EQ-06 | 不存在的设备返回明确错误 |
| EQ-07 | viewer不能修改等级 |
| EQ-08 | 数据库自身约束拒绝非法等级 |

失败迁移/数据丢失的生产回滚不是本样例已验证能力。真实方案需数据备份、兼容发布
和forward-recovery/rollback评估，不能从内存SQLite用例推断生产安全。
