# M1 host capability snapshot: capture integrity, not host authentication

Candidate incremental change stacked on PR #19. No release or live-host gate is
promoted. The existing host_contract preflight remains offline and fail-closed.

## Captured provenance

A successful schema capture adds source (`installed_codex` or `supplied_schema`),
strictly parsed Codex version, SHA-256 of the exact schema bytes, random capture ID,
UTC capture time, and SHA-256 over the entire report excluding the digest itself.
Version and schema probes use the same resolved executable path. Version-probe
failure or unexpected output is UNKNOWN, never echoed. Imported schema always has
UNKNOWN version; it cannot borrow a locally installed version. Paths, hostname,
credentials, raw stderr and schema contents are not emitted.

The digest binds capability declarations and every provenance field. Each capture
gets a distinct ID, even if two hosts have identical versions and schemas. Evidence
referring to one capture must retain that exact capture digest, not just a version.
Changing source, version, schema hash, capture ID or declared proof state invalidates
the reference. The capture is not automatically wired into execution gates yet.

## Verify a saved capture

```
python3 collaboration/host_contract.py > host-snapshot.json
python3 collaboration/host_contract.py --schema TurnStartParams.json > imported-snapshot.json
python3 collaboration/host_contract.py --verify-snapshot host-snapshot.json --expected-snapshot-sha256 DIGEST_RETAINED_SEPARATELY
```

The first two commands still exit 2 when required restricted-read declarations are
absent. A valid blocked snapshot is useful evidence of a missing declaration, not
a passing host. Verification exits 0 only for CAPTURE_INTEGRITY_MATCH, otherwise 2.
It checks the saved bytes semantically against an independently retained expected
digest, without running Codex. Do not derive the expected digest from the same
untrusted file at verification time: that would detect nothing about substitution.

## Honest boundary

A hash is not a signature. Someone able to replace both snapshot and expected digest
can forge this record. Random capture IDs distinguish observations, not machines.
This does not authenticate a host, stop binary replacement between probes, prove
sandbox enforcement, or prove native agent execution. A repeated capture is a new
observation and must not silently reuse the prior capture identity. Live provenance
and journal/receipt binding remain future work and require actual host evidence.
