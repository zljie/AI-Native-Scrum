# 检查配置入口而不只检查脚本

旧自检直接运行 `goal_flow.py`，绕过 `.codex/hooks.json` 的命令；脚本检查通过，实际启动却依赖 `git rev-parse`，在非 Git 根目录失败，在子仓库中也可能选错根路径。

本轮回放修复前的已提交版本复现故障（不是修改前执行的 TDD RED）。修复后从配置读取命令，在非 Git、Git、多子仓库及含空格的嵌套目录运行；脚本按自身所在位置读取 Goal。新回归同时拒绝旧命令并验证真实启动结果。

复用入口：`python3 scripts/check_bootstrap.py`，需 bash、sh、python3 和 Git（Git 仅用于隔离测试夹具）。已有非空配置重跑不会升级，必须先比较并获准更新。

证据：[本轮回归](../../generated/reports/2026-10-14-non-git-dev-flow.txt)。这证明配置命令在 shell 下的启动与输出；Codex 项目信任、原生 UI 和真实业务验收尚未验证。新经验保持 candidate，收益未测量。
