# 协作回执与交接门禁

planned/requested/started/completed/handoff accepted/业务接受是不同事实。
确定性夹具也能产出文件、运行SQLite测试和完整事件，不能因此声称真实模型协作通过。
必须按运行端来源核验独立实例/turn；fixture模式不能进入真实运行或通过发布检查。

下游推进依赖当前版本交接接受，不依赖发送方“完成”的文字。返工保存revision和
失败记录，范围/版本变化使相关依赖失效。写入中断处于applying时，必须继续保留
写范围占用，恢复核验前不得当作闲置范围交给另一任务。

原有evidence.py仍负责真实RED/GREEN。协议日志只能关联结果，不能替代它、身份认证
或用户最终验收。本条基于候选实现的本地回归，真实Codex宿主试跑尚未完成；无收益数据。

## 2026-11-12 适用边界补充（PR #17，candidate）

远程 Codex 0.167.1 首轮验收反馈在已登录、multi_agent 开启的宿主上仍未拿到完整的原生子线程生命周期；沙箱与宿主分别返回 `RUNTIME_DISCONNECTED` / `RUNTIME_REJECTED`，但尚无分阶段 JSON-RPC 错误证据。不能将“CLI 能运行”“父线程有 wait”“宿主登录”提升为已通过原生委派验收，也不能据此推断 Agent 不可用。此判断与本条“启动回执、交接接受、发布验收分别判断”的适用条件一致。

框架候选 PR #17 复用既有 CodexAdapter 和控制器，仅追加**请求阶段 + 标准错误码类别**的白名单诊断、负例测试、Bootstrap 同步；不直接记录或输出服务端 message/data，不扩大受限只读沙箱或授权。协议/fixture 测试不能证明实际宿主兼容；明确版本与根因须由远程操作者的真实脱敏证据确认。此条仍保持 `candidate`，收益未测量。

## 2026-11-12 离线宿主契约预检（candidate）

云端 Codex 0.167.0-alpha.4 的实际导出 Schema 未声明所需受限读取字段；新增 host_contract.py 对该情形返回 BLOCKED，不以只读模式名称推断目录限制有效。声明能力仅是 E0/契约证据，仍需实测 enforcement、认证和原生子 Agent。不能把该云版本结果当作 VPS 0.167.1 的已证实根因。新增离线回归覆盖不支持、外部引用不加载、循环引用、声明不等于验收与错误脱敏。收益未测量。
