# 本地优先的驾驭工程可观测性

依据：用户要求“按照这个期望帮我完成本次迭代”，实现运行证据与数据驱动迭代。此指令授权开发，不等于已验收实现或测得收益。

## 决策提案
在现有 Runner、原生 Hook 和 Gate 调用边界增加可选元数据采集；默认关闭。原子事件文件保存在忽略目录，不部署遥测服务器。规范保留在 Schema；架构决定沿用 wiki/decisions，不创建第二份 ADR 正本。

候选方案包括集中式 OpenTelemetry 服务、全会话 transcript 采集、仅由 Agent 自述。前者增加部署成本，后者有隐私与真实性边界。第一轮采用标准库、本地可检验事件与独立实验评估；以后仅根据实际规模和收益决定集中化。

## 明确取舍
不会自动创建子 Agent；不会用读取 Skill 文件证明执行；不会将进程成功当验收。事件有本地 I/O 开销、未认证来源及未覆盖路径。JSON Schema、单测和 CI 不能证明真实宿主兼容，需登录环境烟测。

## 验证与回滚
验证真实/模拟分离、空数据、失败、超时、用量去重、升级保留与权限不扩张。不开启采集即可保持旧行为；disable 停采但保留历史。若显著增加操作负担或无法得到真实用量，先停采再修复，不补造数据。

## 状态
候选实现提交 PR 后由人评审；真实运行效益尚未测量。
